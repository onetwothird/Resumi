# Production readiness: security, performance, and correctness fixes

Ten commits, each independently revertable. Full code audit of the app
(31 route handlers across 20 files, Prisma schema and all 7 migrations,
middleware, build config).

`npm audit`: **1 critical + 8 high → 0 critical + 7 high**

## Ship blockers

## What was verified, not assumed

**Authorization is genuinely sound and was left alone.** Zero cross-tenant
IDOR across resumes, messages, notifications, applications, jobs. Every
lookup is scoped by `userId`. `api/applications/[id]/route.ts` is the
reference pattern. Nothing here was rewritten.

**One finding I downgraded after tracing it:** `POST /api/jobs/[id]/apply`
accepted an unchecked `resumeId`, which looks like an IDOR. It is not —
`applicants/[applicantId]/page.tsx:48-50` resolves it via
`application.user.resumes.find(...)`, already scoped to the applicant's own
resumes, so a forged id resolves to `undefined` and falls back to their own
resume. Still closed (defence in depth + the job id/status were genuinely
unchecked), but described as latent rather than exploitable in the commit.

**One thing I nearly broke:** I initially enum-restricted `role` in the
profile schema. `ProfileClient.tsx:212` shows that field is a free-text
professional headline ("Full Stack Developer"), not an account role. Caught
before commit and reverted to a length-capped string.

## Also in here

- `fix(api)` — 12 handlers returned `error.message`, leaking table/column/constraint names. Replaced with `internalError()`.
- `fix(privacy)` — `/u/[username]` rendered `User.email` unconditionally on world-readable, enumerable pages. Now opt-in via `User.showEmail` (default false) with a toggle in the profile form.
- `chore(deps)` — removed `html2pdf.js`, `pdf-parse`, `@clerk/themes`, `@tailwindcss/vite` (zero imports) and 3 dead components (~575 lines). `BuilderClient.tsx` called `/api/resumes/[id]`, a route that never existed.
- `perf(server)` — deleted two hardcoded `await setTimeout(1000)` calls; dashboard was fetching every JSON blob then discarding it; both dashboards made a Clerk round-trip per render to read a claim already in the session token.
- `perf(db)` — applicants page did one Clerk call per applicant (N+1); pooled connections now have a 10s connect timeout instead of waiting forever.

## Required before deploy

```bash
npx prisma migrate deploy
```

Two migrations: `RateLimit` table, `User.showEmail`. The rate limiter
**fails open by design** — if the table is missing it logs an error and
allows traffic rather than 500-ing every AI feature.

## Two things needing your attention

1. **Testimonials will disappear from the landing page.** Nothing has a
   moderation UI yet, so submissions land as `approved=false` and stay
   invisible. To approve the existing backlog:
   ```sql
   UPDATE "Testimonial" SET "approved" = true WHERE "approved" = false;
   ```
   Either build a moderation view, or accept that public testimonials are
   effectively off until then.

2. **Existing users' emails stop showing** on public profiles. That is the
   intended safe default; the toggle brings it back.

## Deliberately not changed

- `src/app/template.tsx` — root-level client wrapper with a full-page
  `blur(4px)` transition on every navigation. A real compositing cost, but
  removing it changes the feel of the whole app, so it's your call.
- The 7 remaining high advisories are Prisma CLI/dev-only and transitive
  (fast-uri, js-yaml, nanoid, sharp, mysql2). `npm audit`'s suggested fix
  is to **downgrade** Prisma 7 → 6, which would be a regression. Not applied.
- Prisma/Neon/Clerk stack, and the `Json` resume columns — ownership is
  already structurally unbypassable, so normalizing them buys nothing.
